# تحليل فروع Harbor واختيار أساس Windows مستقر

تاريخ الفحص: 2026-10-20. هذا تقرير قراءة فقط لسجل Git ومحتوى رؤوس الفروع؛ لم أدمج أو أزل أي فرع، ولم أبنِ المشروع أو أشغّل اختبارات محلية.

## النتيجة العملية

لنسخة Windows ذات أساس مستقر، أوصي باستخدام `origin/stable-branch` (الإصدار `0.9.22`، SHA `f103b0d6`) كخط التطبيق، والاستفادة من `origin/coxde/windows-stable-installer` (SHA `74163e42`) كمرجع قريب لإعداد حزمة Windows. فرع المثبّت متقدم على stable باثنين من commits فقط: `687cfb4f` يغير workflow لإنتاج مثبت Windows وأصول mpv، و`74163e42` يضيف تبعية `libudev` لبناء Linux. احتفظ بتغيير Windows بعد مراجعة إعدادات workflow وسجل CI قبل اعتبار وجود commit دليلاً على نجاح تثبيت فعلي. لا تنقل تغيير libudev إلى Windows.

الاختيار يثبت خط التطبيق عند stable، ولا يعني أن stable أحدث خط تطوير. `origin/main` هو `0.9.21` و`origin/stable-branch` هو `0.9.22`، لكنهما متباعدان: عند نقطة الالتقاء `8e21bb13` يوجد 81 commit في stable غير موجود في main و46 في main غير موجود في stable. أما `origin/beta-branch` فهو `0.9.132`، ويحتوي 586 commit غير موجود في stable مقابل commit واحد فقط في stable غير موجود في beta. لذلك لا تدمج beta دفعة واحدة. اختر ميزة واحدة، افحص فرقها بالنسبة إلى stable، ثم أضفها مع ترجمتها واختبارات السلوك المناسبة.

## منهج ونطاق المقارنة

الحصر يشمل 20 فرعاً فعلياً تحت `origin/`: `main`, `stable-branch`, `beta-branch`, `coxde/windows-stable-installer`, `Talal1011-patch-1`، الفروع المسماة `feat/*` و`fix/*`، و`port/manga`. استُبعد المرجع الرمزي `origin/HEAD`؛ ظهوره باسم `origin` في إخراج مختصر لا يجعله فرعاً. أخذت رؤوس SHA من refs المحلية وقت الفحص. قياسات عدد commits تصف اختلاف ancestry فقط، ولا تثبت أن السلوك غائب: قد تدخل ميزة إلى فرع آخر بتغيير مختلف أو تتطور بعد نقلها. لذلك فحصت وجود ملفات أو سلوك ذي صلة في stable/main/beta حيث أمكن. حالات «جزئي/تحقق» تعني أن وجود السطح أو الملف لا يثبت تكافؤ السلوك كاملاً.

## ترتيب ما يستحق النقل إلى stable

بعد تثبيت أساس التطبيق والمثبت، الأولوية من الفروع التي تبدو قابلة للفصل هي فلتر التدفقات المحفوظ (`899a3454`) ثم تقييم الحلقة (`7bbcfe2d`) إذا كانت مطلوبة. ترجمة العربية/البرتغالية تستحق فحص مفاتيح locale الناقصة دون نقل ملفات JSON القديمة. أما ملفات شاشة التوقف وASS وSMTC ومدير التنزيل والطابور، فسطحها الأساسي موجود بالفعل على stable؛ المطلوب إثبات إصلاح بعينه قبل إعادة نقله. اجعل تغييرات Linux/Nvidia وlibmpv وmacOS خارج دفعة Windows.

## حدود الأدلة

هذا تحليل source/history فقط. لم أتحقق من ناتج GitHub Actions أو تشغيل تطبيق Windows أو سلوك المثبت والمشغل؛ أسماء commits التي تقول «verified» ليست بحد ذاتها سجل نجاح CI أو اختبار runtime. قبل وصف النسخة بأنها صالحة للمشاهدة اليومية، يلزم دليل تشغيل Windows فعلي للمثبت والتشغيل والمشاهدة.
